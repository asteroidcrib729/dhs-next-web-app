## PostgreSQL migration contract

`prisma/schema.prisma` uses `provider = "postgresql"`. `src/lib/prisma.ts` creates a cached Prisma Client using `@prisma/adapter-pg` and the server-only `DATABASE_URL`. The generated client remains in ignored `src/generated/prisma`.

The old MySQL migration created `Contact` while the schema model was named `contact`. The new PostgreSQL baseline is generated from the current schema, so the table is consistently `contact`. Fields, nullable values, Boolean defaults, and timestamps are preserved. PostgreSQL text fields also accept contact messages longer than the old migration's 191-character limit.

The baseline in `prisma/migrations/20261022000000_postgresql_init` initializes a **fresh PostgreSQL database**. Do not apply it to an unrelated populated database. No external MySQL database was accessed or changed, and no user data was migrated. Existing external data requires a separate migration plan. Prisma's generated SQL uses its standard `SERIAL` integer primary key for `autoincrement()`.

Client generation, formatting, schema validation, and page builds do not need credentials. Actual persistence needs `DATABASE_URL`. The database check refuses to write unless `DATABASE_TEST_ALLOW_WRITE=true`; use it only against an isolated database. It performs create/read/update/delete inside a transaction and leaves no test inquiry behind. Drift checking compares the initialized database to the Prisma schema.

## Formatting contract

Run `npm run format` before completing code changes. It applies Prettier to maintained TS/TSX, JS/MJS, CSS, JSON, YAML, and Markdown, then formats the Prisma schema. Run `npm run format:check` to verify without changing source files; Prisma formatting is checked on a temporary copy. Generated code, build artifacts, public media, local data, and npm-generated lockfile formatting are excluded. Migration SQL is generated by Prisma.

`npm run check` combines format checking, ESLint, type checks, schema validation, and asset verification. CI also builds the site. Public media remains covered by exact hashes and 5 MiB/file and 20 MiB total budgets.

## CI and security contract

| Workflow           | Checks                                                                                                                | Triggers                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `code-quality.yml` | Formatting, lint, types, schema, assets, build on Linux/Windows; PostgreSQL 18 migrations, drift and CRUD; Actionlint | Push, pull request, merge queue, manual         |
| `security.yml`     | Complete dependency audit artifact, high/critical production vulnerability gate, redacted full-history Gitleaks scan  | Push, pull request, merge queue, weekly, manual |
| `codeql.yml`       | JavaScript/TypeScript and GitHub Actions security analysis                                                            | Push, pull request, merge queue, weekly, manual |

Actions are pinned to full commit hashes. Gitleaks and Actionlint downloads are version-pinned and SHA-256-verified. Workflow tokens are read-only except the CodeQL job's required security-events write permission. Pull requests use `pull_request`, and checkout does not retain credentials. Builds and database jobs do not use application secrets or send email. The CI PostgreSQL password is only for the disposable service container.

The full dependency audit is retained for review; production high/critical findings block CI. The existing five high findings are development-only and trace to the unpatched `braces` advisory documented in [verification](verification.md). Development findings are visible in the workflow summary and audit artifact; they are not silently counted as resolved. Audit service failures also fail the job. Reassess the development findings regularly and strengthen the gate when a compatible patch is available.

Dependabot checks npm and Actions weekly at 10:00 Asia/Karachi. Next.js, Prisma, React, and Tailwind updates are grouped to keep related packages together. Prisma remains on matching stable client/CLI/adapter versions. Node typings stay on the runtime's major; TypeScript versions outside the parser's declared range and ESLint major upgrades require manual compatibility review. No automatic merge is configured.

GitHub must have Actions enabled. CodeQL advanced code scanning must be supported and enabled for the repository; private repositories may require a suitable GitHub security plan. Do not enable a duplicate default CodeQL setup alongside this advanced workflow. Branch protection/rulesets and Dependabot alerts/security updates are repository settings, not enabled by merely adding these files. Set required checks after observing their names in the first successful hosted run.
